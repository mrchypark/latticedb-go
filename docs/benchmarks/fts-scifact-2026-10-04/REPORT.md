# SciFact FTS 실데이터 평가 — 2026-10-04

#219의 쿼리 기능 네 항목은 v0.11.0에서 구현됐다. 남아 있던 FTS 실데이터 비교를 수행했다. **공통 조건의 BM25 검색은 Go와 Zig 모두 300개 질의에서 같은 상위 10개 문서 순서를 반환했다.** 원문을 사용하는 Go 검색에서는 BM25가 기본 frequency보다 높은 관련성 점수를 보였다. 기본값은 변경하지 않는다.

## 평가 조건

[BEIR SciFact 공식 배포](https://github.com/beir-cellar/beir/wiki/Datasets-available)의 전체 5,183개 논문 제목·초록과 test 질의 300개, 해당 정답 문서 판정을 사용했다. 원문 데이터의 SHA256을 고정하고, 문서·질의 매핑과 준비된 파일 해시를 [manifest](manifest.json)에 보관했다. 원문 텍스트는 저장소에 포함하지 않았다.

Go 엔진은 v0.11.0 `0e5a119173bae1301d9d776828e426a52ef004dd`, Zig 원본은 #219의 기준 `827891e2c6fd55d13aa8f8284a7c7043f68b60fd`다. macOS 26.3 arm64, Go 1.27.1, Zig 0.16.0 ReleaseFast를 사용했다. [환경·도구 해시](environment.json), [실행 순서](execution-order.json), [재현 방법과 측정 정의](REPRODUCE.md)를 함께 제공한다.

각 설정을 순차 실행하고, 3개 라운드에서 시작 설정을 교대했다. 매번 새 디스크 인덱스를 만들고 닫은 뒤 다시 열었다. 전체 질의를 한 번 warmup한 다음 300개를 측정했다. 설정별 지연 표본은 900개다. 품질 점수는 세 반복의 순위가 같음을 검사한 뒤 질의별 한 번 계산했다. CPU 격리·주파수 고정이나 다른 시스템 활동 통제는 하지 않았다.

## 공통 조건 비교

문서에는 소문자 ASCII 영숫자 토큰을 사용하고 중복 출현 횟수를 유지했다. 64자 초과 토큰은 통째로 제외했다. 질의는 Zig 예약어 `and/or/not`를 양쪽에서 제외하고, 중복을 제거한 뒤 최대 32개 토큰을 사용했다. 32개를 초과하는 질의는 없었다. 다른 stopword 제거, stemming, fuzzy는 적용하지 않았다. 두 구현의 BM25 파라미터는 k1=1.2, b=0.75, 정확 일치 OR 검색이다.

| 구현·측정 범위 | nDCG@10 | Recall@10 | MRR@10 | 중앙 지연 | P95 지연 |
|---|---:|---:|---:|---:|---:|
| Go 공개 DB API, record cache 없음 | 0.6607 | 0.7876 | 0.6273 | 5.930 ms | 11.913 ms |
| Zig FTS 컴포넌트, 64 MiB buffer pool | 0.6607 | 0.7876 | 0.6273 | 2.311 ms | 4.840 ms |

**300/300 질의의 top-10 순서가 일치하고 평균 문서 중첩률은 100%다.** 점수 계산의 부동소수점 정밀도까지 같다는 주장은 아니다. 저장 계층과 캐시, API 경계가 다르므로 위 지연을 언어 자체나 동등한 전체 DB 성능의 배수로 바꾸지 않는다. Zig 어댑터는 두 BTree root ID를 직접 보존해 재오픈하며, 그래프·catalog·트랜잭션·복구 API 전체를 거치지 않는다.

양쪽은 작은 검증 데이터에서도 N=3, 총 토큰=7, `rare` 검색 순위 document2 → document1을 확인했다. Go 테스트는 독립 계산식과 점수를 비교한다. Zig의 [검증 로그](zig-fixture.tsv)도 같은 점수 약 0.6133946과 0.32026795를 반환한다. 전체 공통 문서의 토큰 합계 1,167,322개도 Zig 재오픈 통계와 일치했다.

## Go 원문 검색 선택지

이 표는 변환하지 않은 Unicode 원문과 질의를 사용한다. Zig와의 토큰 의미를 맞춘 표와 구분해야 한다. 세 설정 모두 Go 공개 DB API와 같은 디스크·예산 조건을 사용했다.

| 설정 | nDCG@10 | Recall@10 | MRR@10 | 중앙 지연 | P95 지연 |
|---|---:|---:|---:|---:|---:|
| Frequency — 기존 기본값 | 0.0959 | 0.1750 | 0.0720 | 6.159 ms | 12.892 ms |
| BM25 | 0.6617 | 0.7909 | 0.6276 | 6.287 ms | 12.161 ms |
| BM25 + English Porter | 0.6889 | 0.8222 | 0.6523 | 6.859 ms | 14.509 ms |

이 데이터에서는 문서 길이와 문서 빈도를 반영하는 BM25가 더 높은 관련성 순위를 냈다. Porter를 추가한 설정이 가장 높은 관측 점수를 냈다. 통계적 유의성이나 다른 분야·언어에서의 우위를 검증한 것은 아니다. 서비스별 데이터로 선택해야 하며, 이번 작업은 `FTSSearchOptions.Scoring`과 `Analyzer`의 기본값을 바꾸지 않는다.

## 검증과 한계

- 입력 누락, 중복·알 수 없는 결과 ID, API 오류, 비정상 점수, 빠진 라운드는 평가 실패로 처리한다. 결과가 없는 질의도 분모에 포함한다. 모든 설정에서 300개 질의 × 3라운드를 확인했다.
- nDCG는 `2^relevance-1` gain, Recall은 전체 양성 정답 문서 수를 분모로 한다. 무응답·적은 결과·복수 정답·등급별 정답의 알려진 값을 단위 테스트로 확인했다. 정답에 없는 문서는 제공된 판정 기준에서 비관련으로 처리한다.
- 첫 진단 실행은 Zig 예약어를 제외하지 않아 22개 질의 순위가 달랐다. 그 실행을 최종 집계에서 제외하고, 준비 코드를 수정한 뒤 모든 설정을 다시 측정했다. 초기 차이를 부동소수점 오차나 엔진 결함으로 보고하지 않았다.
- 영어 과학 문서 한 데이터셋, 정확 일치 top-10, warm 단일 클라이언트 읽기만 측정했다. 한국어, fuzzy 품질, 콜드 캐시, 동시 부하, RAM보다 큰 검색 인덱스, 쓰기 내구성의 비교 근거는 아니다.
- Go 검색 예산은 MaxWork=2^40, MaxBytes=256 MiB로 명시했다. 이는 기본 예산이나 RSS 보장 검증이 아니다. Cypher 원본 레코드 읽기의 메모리 문제는 [#222](https://github.com/mrchypark/latticedb-go/issues/222)에서 별도로 추적한다.
- Pro가 평가 설계를 검토했고, 문서·평가 완전성 검사, 실효 토큰 의미 검증, 실행 순서 교대를 반영했다. 이는 전체 변경 코드에 대한 최종 Pro 승인이라는 뜻은 아니다.
